# くらし通帳（household-ledger）

iPhone向けの個人用家計管理アプリ。本人の支出、カード請求、立替とPayPayでの回収を区別します。

## 現在できること

- 本人用パスワードの初期設定・ログイン・ログアウト。
- 銀行・現金・PayPay・カード口座の開始日・開始残高と明細による残高管理。開始日と開始残高は後から修正できます。
- 支出・収入・口座間移動・立替配分・一部ずつの回収。
- カード請求の確定／予測／金額不明の区別と、実際の引き落とし記録。
- 分割手数料の本人費用計上。立替回収でカード残債を減らさない集計。
- 家賃等の定期予定と実績を分けた管理。
- PayPay公式CSVの手動補助取り込み。取引番号による重複防止。受取を収入と断定せず、未分類で取り込み。
- JSONバックアップと、既存データを上書きしない追加読み込み。

## 起動

```sh
docker compose up --build
```

以降は `docker compose up`。ブラウザで <http://localhost:5178> を開き、表示名と12文字以上のパスワードを設定します。初回だけサンプルデータを選択できます。実際の家計を記録する場合は選択しないでください。

ポートはMacのループバックだけに公開します。ソースはマウントされ、ReactはHMR、サーバーはwatchで再起動します。SQLiteはDockerの `ledger` 名前付きボリュームで永続化します。データを残すには、ボリュームを削除しないでください。

Node.js 22.13以降が既にある場合、Dockerなしでも実行できます。

```sh
npm ci
npm run dev
```

こちらの保存先は `data/ledger.sqlite` です。Dockerの保存先とは別です。環境変数名は `.env.example` を参照してください（このファイルを自動ではロードしません）。パスワードはscrypt、セッションはランダムトークンのSHA-256で保管します。パスワードのリセット画面は未実装です。

## 検証

```sh
npm test
npm run build
```

立替配分、一部回収、カード元金・手数料、二重記録、同日同額の別明細、不正CSV、バックアップの競合等を検証します。

## 現時点の制限

楽天カード・銀行・PayPayの**自動取得は未実装・未接続**です。CSVは補助手段であり、自動連携の代替として採用した運用ではありません。楽天の実際のCSVを用いた取込、分割変更の自動追跡、各購入の将来返済予定の自動生成も未実装です。

ローカルではSQLite、本番ではFirestoreを使用します。Cloud RunではFirestore・初回設定コード・Secure Cookieが設定されていない場合に起動を拒否します。本人用パスワードでログインし、初期設定にはSecret Managerの確認コードが必要です。デプロイの構成と初回手順は [docs/deployment.md](docs/deployment.md) を参照してください。Firestoreエミュレータは使用しません。

口座には開始日と、その日の始めの残高を登録します。カード口座の未払い額はマイナスで入力します。開始日より前の明細は月ごとの収支には入りますが、残高には影響しません。そのため、過去の明細を後から追加読込しても今の残高は変わりません。開始日のない口座は、すべての明細を残高に含めます。既に開始残高へ含めた手数料を同じ請求で再計上しないよう、導入時の照合が必要です。CSVに開始残高は含まれません。

手入力した明細は、明細一覧から取り消して再入力できます。取り消した記録は残り、「取消済み」一覧から戻せます。回収済みの立替を取り消す場合は、先に回収記録を取り消す必要があります。CSV等で取得元のある明細の訂正、複数人分の立替を画面から一括入力する機能、返金・チケット取消の専用フローは未実装です。

`output/` と家計データはGit対象外です。クラウド費用は利用量と保持するイメージ数に依存します。明細連携サービスの追加費用は0円を目標にします。iPhone実機の表示・ホーム画面追加・本番ログインは利用環境で確認してください。
